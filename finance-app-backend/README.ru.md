# FinTrack Backend API

Современный асинхронный backend‑сервис на FastAPI для приложения FinTrack по управлению личными финансами. Этот RESTful API обеспечивает безопасную аутентификацию, управление транзакциями и категориями, а также предоставляет аналитические отчёты по доходам и расходам.

## Обзор

FinTrack Backend — современный, ориентированный на асинхронную работу Python‑backend, построенный на FastAPI и обслуживающий мобильное приложение на React Native. Сервис реализует двухфакторную аутентификацию по e‑mail (2FA), сессионное управление на основе JWT и предоставляет полноценное API для работы с персональными финансовыми данными: транзакциями, категориями и статистикой.

## Возможности

### Аутентификация и безопасность

- **2FA по e‑mail**: двухэтапный вход с отправкой 6‑значного проверочного кода на почту
- **JWT‑аутентификация**: безопасные токены доступа с настраиваемым временем жизни
- **Безопасность паролей**: хэширование паролей с помощью bcrypt
- **Социальная аутентификация**: поддержка OAuth‑интеграций с Google и Apple
- **Подтверждение e‑mail**: новый пользователь должен подтвердить почту перед доступом к приложению
- **Управление сессиями**: безопасная работа с сессиями с учётом истечения срока кода и ограничения числа попыток

### Управление транзакциями

- **CRUD‑операции**: создание, чтение, обновление и удаление финансовых транзакций
- **Расширенная фильтрация**: фильтрация по типу (доход/расход), категории, диапазону дат, диапазону сумм и по тексту
- **Пагинация**: эффективная работа со списками транзакций большого объёма
- **Мультивалютность**: хранение операций в разных валютах (базово в USD)
- **Регулярные платежи**: пометка транзакций как регулярных
- **Заметки к операциям**: опциональные текстовые комментарии

### Управление категориями

- **Пользовательские категории**: создание, редактирование и удаление собственных категорий
- **Категории по умолчанию**: 12 предустановленных категорий для новых пользователей (Salary, Freelance, Investments, Food & Drinks, Transport, Shopping, Entertainment, Health, Bills & Utilities, Education, Gifts, Other)
- **Типы категорий**: категории для доходов, расходов или обоих типов сразу
- **Визуальная настройка**: иконка и цвет для отображения в интерфейсе
- **Привязка к пользователю**: все категории приватны и доступны только владельцу

### Аналитика и статистика

- **Месячная статистика**: сводный обзор финансов за выбранный месяц
- **Суммарные доходы/расходы**: агрегированные показатели по поступлениям и тратам
- **Баланс**: автоматический расчёт баланса (доходы − расходы)
- **Разбивка по категориям**: распределение расходов по категориям с учётом их цветов
- **Дневные тренды**: динамика доходов и расходов по дням выбранного периода
- **Гибкий период**: фильтрация по произвольным диапазонам дат для пользовательских отчётов

### Инструменты разработчика

- **Сброс базы данных**: dev‑endpoint для полного пересоздания схемы БД
- **Health‑check**: endpoint проверки работоспособности приложения
- **Интерактивная документация API**: Swagger/OpenAPI (доступна в локальной и staging‑средах)

## Технологический стек

- **Фреймворк**: FastAPI 0.129+ (Python 3.14)
- **База данных**: PostgreSQL 17+ с драйвером asyncpg
- **ORM**: SQLAlchemy 2.0 (асинхронный режим)
- **Миграции**: Alembic для управления схемой БД
- **Аутентификация**: python‑jose (JWT), bcrypt (хэширование паролей)
- **E‑mail**: aiosmtplib для отправки почты по SMTP
- **Сервер**: Uvicorn (ASGI, async)
- **Валидация**: Pydantic для запросов и ответов
- **HTTP‑клиент**: httpx для обращения к внешним OAuth‑провайдерам

## Основные эндпоинты API

### Аутентификация (`/api/v1/auth`)

- `POST /auth/signup` — регистрация нового пользователя (возвращает сессию верификации)
- `POST /auth/login` — вход по e‑mail и паролю (возвращает сессию верификации)
- `POST /auth/verify-code` — подтверждение кода и завершение аутентификации (возвращает JWT)
- `POST /auth/resend-code` — повторная отправка кода подтверждения
- `POST /auth/social` — вход через Google/Apple OAuth (обходит 2FA)
- `GET /auth/me` — получение текущего пользователя (по JWT)
- `POST /auth/logout` — выход (по JWT)

### Транзакции (`/api/v1/transactions`)

- `GET /transactions` — список транзакций с фильтрами и пагинацией
- `GET /transactions/{id}` — получение конкретной транзакции
- `POST /transactions` — создание транзакции
- `PUT /transactions/{id}` — обновление транзакции
- `DELETE /transactions/{id}` — удаление транзакции
- `GET /transactions/stats` — месячная статистика и аналитика

### Категории (`/api/v1/categories`)

- `GET /categories` — список категорий пользователя
- `POST /categories` — создание категории
- `PUT /categories/{id}` — обновление категории
- `DELETE /categories/{id}` — удаление категории

### Разработка (`/api/v1/dev`)

- `POST /dev/reset-db` — сброс и пересоздание всех таблиц БД (только для разработки)

## Схема базы данных

### Таблица пользователей (Users)

- `id` (UUID, PK)
- `email` (String, уникальный, NOT NULL)
- `password_hash` (String, NULL для соц. входа)
- `name` (String, NULL)
- `avatar` (String, NULL — URL)
- `provider` (String, NULL — "google", "apple" или null)
- `is_verified` (Boolean, по умолчанию False)
- `created_at` (Timestamp)

### Таблица категорий (Categories)

- `id` (UUID, PK)
- `user_id` (UUID, FK → users.id)
- `name` (String, NOT NULL)
- `icon` (String, NOT NULL — имя иконки Ionicons)
- `color` (String, NOT NULL — hex‑цвет)
- `type` (String, NOT NULL — "income", "expense" или "both")

### Таблица транзакций (Transactions)

- `id` (UUID, PK)
- `user_id` (UUID, FK → users.id)
- `type` (String, NOT NULL — "income" или "expense")
- `amount` (Decimal(12,2), NOT NULL — хранится в USD)
- `currency` (String(3), NOT NULL — код валюты на момент ввода)
- `category` (String, NOT NULL — имя категории)
- `note` (Text, NULL)
- `date` (Timestamp, NOT NULL)
- `recurring` (Boolean, по умолчанию False)
- `created_at` (Timestamp)

### Таблица кодов подтверждения (Verification Codes)

- `id` (UUID, PK — session_id)
- `user_id` (UUID, FK → users.id)
- `code` (String(6), NOT NULL — 6‑значный код)
- `purpose` (String(10), NOT NULL — "signup" или "login")
- `expires_at` (Timestamp, NOT NULL — +10 минут от создания)
- `used` (Boolean, по умолчанию False)
- `attempts` (Integer, по умолчанию 0 — число неверных попыток)
- `created_at` (Timestamp)

## Безопасность

- **Подтверждение e‑mail**: все новые пользователи должны подтвердить почту, прежде чем получить доступ к API
- **Срок жизни кода**: коды подтверждения действуют 10 минут
- **Ограничение попыток**: максимум 5 неверных попыток ввода кода на одну сессию
- **Ограничение повторных отправок**: максимум 3 повторных отправки кода на сессию
- **Срок жизни JWT**: настраиваемое время жизни токена (по умолчанию 60 минут)
- **Хэширование паролей**: bcrypt с автоматической генерацией соли
- **CORS**: настраиваемый CORS для интеграции с фронтендом
- **Валидация ввода**: все данные проверяются Pydantic‑схемами
- **Защита от SQL‑инъекций**: использование ORM SQLAlchemy

## Переменные окружения

Создайте файл `.env` в корне проекта со значениями:

```env
# База данных
DATABASE_URL=postgresql+asyncpg://username:password@localhost:5432/fintrack

# JWT‑конфигурация
JWT_SECRET=your-secret-key-change-in-production
JWT_ALGORITHM=HS256
JWT_ACCESS_TOKEN_EXPIRE_MINUTES=60

# Окружение
ENVIRONMENT=local  # Доступные значения: local, staging, production

# SMTP (для отправки кодов подтверждения)
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-email@gmail.com
SMTP_PASSWORD=your-app-password
SMTP_FROM_EMAIL=your-email@gmail.com
VERIFICATION_CODE_EXPIRE_MINUTES=10
```

## Установка и запуск

### Вариант A: Docker (рекомендуется)

Убедитесь, что установлены [Docker](https://docs.docker.com/get-docker/) и [Docker Compose](https://docs.docker.com/compose/install/).

1. **Клонируйте репозиторий**

   ```bash
   git clone <repository-url>
   cd finance-app-backend
   ```

2. **(Опционально) создайте `.env`** в корне проекта, чтобы переопределить значения по умолчанию (например, `JWT_SECRET`, SMTP‑настройки). Compose автоматически использует `DATABASE_URL` для сервиса `db`.

3. **Соберите и запустите контейнеры**

   ```bash
   docker compose up --build
   ```

   API будет доступен по адресу **http://localhost:8000**. PostgreSQL — на порту 5432. Документация: http://localhost:8000/docs

4. **Запуск в фоне**

   ```bash
   docker compose up -d --build
   ```

5. **Остановка и удаление контейнеров**

   ```bash
   docker compose down
   ```

   Добавьте `-v`, чтобы удалить том с данными Postgres: `docker compose down -v`.

### Вариант B: Локальная установка

1. **Клонируйте репозиторий**

   ```bash
   git clone <repository-url>
   cd finance-app-backend
   ```

2. **Создайте виртуальное окружение**

   ```bash
   python3 -m venv venv
   source venv/bin/activate  # Windows: venv\Scripts\activate
   ```

3. **Установите зависимости**

   ```bash
   pip install -r requirements.txt
   ```

4. **Создайте базу данных PostgreSQL**

   ```bash
   createdb fintrack
   ```

5. **Настройте переменные окружения**

   ```bash
   cp .env.example .env  # если есть пример
   # Отредактируйте .env под свою среду
   ```

6. **Выполните миграции БД (если используете Alembic)**

   ```bash
   alembic upgrade head
   ```

7. **Запустите dev‑сервер**

   ```bash
   uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
   ```

8. **Откройте документацию API**

   - Swagger UI: http://localhost:8000/docs
   - ReDoc: http://localhost:8000/redoc

## Примечания по разработке

- **Сброс БД**: в режиме разработки (`ENVIRONMENT=local`) приложение может автоматически удалять и пересоздавать все таблицы при старте (реализовано в lifespan‑функции `app/main.py`).
- **Fallback для e‑mail**: при отсутствии настроенного SMTP коды подтверждения выводятся в консоль сервера.
- **Документация API**: Swagger‑документация доступна только в окружениях `local` и `staging` из соображений безопасности.
- **Асинхронность**: все операции с БД выполняются через async/await.
- **Изоляция транзакций**: каждый HTTP‑запрос использует отдельную сессию БД с корректной обработкой транзакций.

## Формат ответов API

### Успешные ответы

- `200 OK` — успешные GET/PUT‑запросы
- `201 Created` — успешные POST‑запросы (ресурс создан)
- `204 No Content` — успешные DELETE‑запросы

### Ошибки

Все ошибки имеют формат:

```json
{
  "detail": "Описание ошибки"
}
```

Наиболее частые коды:

- `400 Bad Request` — неверные данные или истёкший код подтверждения
- `401 Unauthorized` — отсутствует или некорректен токен
- `403 Forbidden` — пользователь не верифицирован или нет прав
- `404 Not Found` — ресурс не найден
- `409 Conflict` — e‑mail уже зарегистрирован
- `429 Too Many Requests` — превышен лимит попыток/повторных отправок кода

## Тестирование

API можно тестировать:

- через **Swagger UI** (`/docs`)
- с помощью **curl**
- в **Postman**
- из фронтенд‑приложения (React Native / Expo)

Пример потока регистрации:

1. `POST /auth/signup` с e‑mail, паролем и именем
2. Получить `session_id` в ответе
3. Взять 6‑значный код из письма (или из логов сервера в dev‑режиме)
4. `POST /auth/verify-code` с `session_id` и кодом
5. Получить JWT‑токен
6. Использовать токен в заголовке `Authorization: Bearer <token>` для защищённых эндпоинтов

## Рекомендации для продакшена

- **JWT_SECRET**: используйте длинный случайный секрет
- **SMTP**: подключите надёжный почтовый сервис (Gmail, SendGrid, Mailgun и т.п.)
- **Резервное копирование**: настройте регулярные бэкапы PostgreSQL
- **Rate limiting**: добавьте ограничение числа запросов к критичным эндпоинтам
- **Мониторинг и логирование**: интегрируйте систему мониторинга и централизованное логирование
- **HTTPS**: используйте HTTPS (через reverse‑proxy, например Nginx)
- **Переменные окружения**: никогда не коммитьте `.env` в репозиторий
- **Миграции БД**: для всех изменений схемы используйте Alembic
- **Отключение auto‑drop**: в продакшене необходимо убрать автоматическое удаление таблиц из lifespan‑логики
